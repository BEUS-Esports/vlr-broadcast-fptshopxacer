- Local tournament-entry ownership, participant validation, conflicting-command rejection, and resets when the selected game changes or clears.
- Provider-independent operator cards on In-Game only, with current revisions, explicit pending status, correction commands and ceremony expiry feedback.
- One center banner shared by Native Preview, Live Data Preview (including no provider or unmapped provider identity), both Large Previews and shown Program.
- Current live controls reach held Program content without recapturing it. Provider mode changes and banner commands preserve the upstream connection.
- Strict v3 snapshots and a validated, persisted-publication-only v2 upgrade with idle banner defaults. The provider envelope is unchanged.
- Single-slot rendering, automatic ceremony-to-pause arbitration, no retained banner after Hide, fully opaque Tactical-to-Technical replacement, absolute-deadline enter/exit animation, timer cleanup and reduced motion.
- Migration `0009_in_game_match_controls.sql`, with recreation and populated Phase 6 forward-upgrade tests.

The plan was clarified to keep v2 compatibility at the persisted read boundary, reuse the existing full-live-control Program overlay, keep motion within the original event window, and separate software implementation from real capture acceptance.

### Existing client-suite failures

The failures are confined to `Pregame.svelte.test.ts` (7) and `Statistics.svelte.test.ts` (5). These tests render the existing template directly, bypassing the modified `GraphicRenderer`. The template source is unchanged by Phase 6.1; fixture changes only bump the snapshot version and add idle live-control defaults.

Copies of the original HEAD tests, with their original v2 fixtures, reproduced exactly the same 12 failures and 2 passes. Temporary diagnostic copies were then removed. Failures include old text/frame expectations and statistics-coverage/agent-overflow expectations against the existing template. Those semantic assertions were preserved; broader template/test maintenance remains separate work. The complete client suite is therefore **not fully green**.

Default-concurrency server verification initially suffered unrelated timeout failures while other validation ran. The capped two-worker rerun passed without changing implementation or test timeouts.
