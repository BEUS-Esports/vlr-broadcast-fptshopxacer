# Phase 5.1 implementation and verification

Date: 2026-10-02. Implements the approved [Graphics Control workflow and Test GFX v2 plan](./2026-10-02-phase-5.1-graphics-control-workflow-test-gfx-v2.md). The repaired plan was preserved. This record supersedes the Phase 5 controller and generic-artwork evidence where behavior changed.

## Implemented behavior

Following the operator's sidebar preference, navigation separates **Preparation** (Teams, Players, Game Resources, Tournaments) from **GFX Control** (Global Settings and the seven graphics). `/admin/graphics` opens Global Settings; the seven `/admin/graphics/<graphic>` routes share Global Setup and canonical preparation editors. Horizontal graphic navigation and overview cards were removed. The Game workspace follows **Info → Lineup → Map Veto → Agent Select → Post-Game Report**. Embedded editor actions use explicit original record IDs and the same management services.

Preview uses the latest saved preparation through the shared renderer, independent of program visibility. Large Preview uses a native modal dialog with visible Close, Escape, focus containment/restoration, and the same saved snapshot. Both scale the fixed 1920×1080 canvas without internal scrolling. Unsaved fields do not appear in Preview.

Show atomically persists a prepared capture for that graphic. Canonical saves and content-control saves update Preview while shown program retains its published capture. Repeated Show preserves the capture; Hide clears it and the next Show publishes the latest saved preparation. Another graphic can publish a newer capture independently. Explicit presentation swap and current-side overrides still act live against held competition identity. Program fails closed when a capture is missing or malformed.

The server rejects changing or clearing live selection while any graphic is shown, including a combined hide-and-switch request. Global Setup follows the shared state across controllers. Dirty preparation retains its original record, revision, rows, and picker labels across refreshes and external selection changes; stale submission rejects rather than writing to the newly selected game. Navigation and explicit discard use the shared draft guard.

Agent Select alone edits lineup agent assignments. Statistics writes parse metrics only and cannot alter agents, including crafted requests. Agent writes leave statistics and import/manual-edit provenance untouched. Post-Game Report shows saved player/agent identity read-only and preserves unknown/null versus measured zero.

Match → Games offers transactional duplication with agent copy OFF by default. Normal creation and duplication share target veto projection, BO/uniqueness checks, and series recomputation. The source revision is checked without modifying it. Target roster/player eligibility and optional active-agent validation occur inside the same transaction. The target receives explicit lineup fields only; results, scores, statistics, MVP, and provenance remain empty. Duplication neither changes live selection nor republishes shown graphics.

## Migration and environment limits

Migration `0007_broadcast_publications.sql` adds persisted capture slots, hides legacy shown graphics, and advances the control revision while preserving selection. Operators must review preparation and Show again after upgrade. The migration and malformed-capture behavior were exercised against disposable databases. The local/event database remains unchanged; rehearse the forward migration against a backup before an event upgrade.

Run a single Node application process: SSE publication remains process-local while captures persist in the database. A multi-process deployment needs shared delivery. The installed SvelteKit 3 adapter requires the intended `ORIGIN` at build time; rebuild after browser tests before starting with a different deployment origin. Authentication and live providers remain outside this phase.

Actual OBS alpha/scaling/clipping, LAN controllers, real Valorant native-HUD compatibility, and provider attribution rehearsal remain separate environment checks. Test GFX v2 and automated browser verification do not claim broadcast readiness.
